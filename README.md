# Telegram-бот: мониторинг заявок на самосвал

Бот мониторит выбранные Telegram-каналы и группы по СПб и ЛО, находит заявки и присылает уведомления в личку с кнопками «Интересно / Не интересно».

Отслеживаемые категории:

| Категория | Эмодзи |
|---|---|
| Нужен самосвал | 🚛 |
| Нужны машины | 🚛 |
| Вывоз грунта / боя | 🚛 |
| Продам вторичный щебень / бой | 🟢 |
| Куплю вторичный щебень / бой | 🔵 |

## Как это устроено

Используются **два аккаунта**:

- **Бот** (`aiogram`) — шлёт уведомления вам в личку и обрабатывает кнопки «Интересно / Не интересно».
- **Ваш личный аккаунт** (`Telethon`) — читает каналы и группы. Это единственный способ стабильно читать и каналы, и группы, в которых нет бота. Аккаунт должен быть участником отслеживаемых групп (публичные каналы читаются без подписки).

Мониторинг устойчив к пропущенным сообщениям: при старте и при добавлении нового канала бот сканирует **историю за сутки** (backfill), дубликаты отсекаются уникальным ключом `(канал, id сообщения)` в БД.

Данные сохраняются в SQLite (`tg_bot_search.db`) — заявки, сообщения, оценки «интересно/не интересно». Это уже задел под будущую CRM, базу клиентов и обучение классификатора.

## Структура проекта

```
app/
├── main.py                    # точка входа, запуск бота + монитора вместе
├── config.py                  # настройки из .env (pydantic-settings)
├── login.py                   # разовая авторизация Telethon-аккаунта
├── db/                        # SQLAlchemy: модели, репозиторий, статистика
├── classification/            # категории + классификатор заявок
│   ├── categories.py          # правила (регулярки) по категориям — сюда редактировать
│   └── classifier.py          # движок сопоставления с оценкой релевантности
├── monitor/telethon_monitor.py  # мониторинг каналов, backfill, resolve ссылок
├── services/job_service.py    # оркестрация: обработать → классифицировать → уведомить
├── services/notifier.py       # формирование уведомления и кнопок
└── bot/handlers.py            # команды бота и обработка кнопок
```

## Быстрый старт

1. Установите Python 3.11+ и создайте окружение:

```bash
cd tg_bot_search
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

2. Настройте `.env`:

```bash
cp .env.example .env
```

Заполните:
- `BOT_TOKEN` — у @BotFather (`/newbot`);
- `ADMIN_TELEGRAM_ID` — ваш id (узнать у @userinfobot — ваш личный не бот-аккаунт);
- `TG_API_ID` и `TG_API_HASH` — на https://my.telegram.org/apps (создать приложение);
- `TG_PHONE` — необязательно, номер для логина первого раза (можно ввести и в консоли).

3. Разово авторизуйте мониторинговый аккаунт:

```bash
python -m app.login
```
Введите номер телефона и код из Telegram. Сессия сохранится в `sessions/`.

4. Запустите бота:

```bash
python -m app.main
```

5. Напишите боту `/start`, затем добавьте источник:

```
/add t.me/имя_канала
/add @имя_группы
/add https://t.me/+invite_hash
```

## Команды

| Команда | Описание |
|---|---|
| `/start`, `/help` | Справка |
| `/list` | Отслеживаемые каналы/группы |
| `/add <username\|ссылка>` | Добавить источник (после добавления аккаунт вступает по invite-ссылке, если возможно, и сканируется история за сутки) |
| `/remove <id\|username>` | Убрать источник |
| `/stats` | Статистика: сообщения, заявки, ваши оценки |

## Настройка классификатора

Категории и правила редактируются в `app/classification/categories.py`. Для каждой категории — список regex-паттернов с весом и паттерны-отрицания (исключение ложных срабатываний).

Точность регулируется в `.env`:

- `MIN_SCORE` — порог релевантности (по умолчанию `3`);
- `GEO_REQUIRED` — `true`, если учитывать заявки только с упоминанием СПб/ЛО;
- `GEO_BONUS` — бонус к баллу за упоминание региона.

Замечание: сообщения **без текста** (только картинка) пока игнорируются — просите в группах писать подпись, либо добавьте распознавание изображений позже.

## Куда расширять

- **CRM / база клиентов**: SQLAlchemy-модели уже изолированы в `app/db`; добавляете таблицы клиентов, сделок, контактов.
- **Сопоставление «куплю/продам»**: категории `sell_rubble` / `buy_rubble` уже разделяются — дальше добавляется связка по товару и гео.
- **Несколько самосвалов / Mini App**: `JobService` не привязан к конкретному водителю — уведомления можно маршрутизировать по собственникам, а `aiogram`-бот легко расширить под Mini App (веб-панель поверх той же БД).
- **Обучение классификатора**: кнопки «Интересно / Не интересно» пишутся в `job_posts.feedback` — это будущий датасет для подстройки правил/ML.

## Ограничения MVP

- Аккаунт Telethon должен быть участником приватных групп (иначе их не прочитать).
- Автовступление работает только по invite-ссылкам; в некоторых группах нужен ручной вход администратором.
- Иногда «нужны машины» может быть про легковые — отсекайте кнопкой 👎; оценки накапливаются и со временем правила можно уточнить.
